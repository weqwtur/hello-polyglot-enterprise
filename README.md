# Polyglot Enterprise Hello World

Один `Hello, World!`. Вісім мов.

```
                  "Hello, World!"
                         |
                         v
   +-----------+   +-----------+   +-----------+   +-----------+
   |   Java    |-->|    C++    |-->|  Node.js  |-->|   Perl    |--+
   | 95 класів |   | templates |   | 40 middl. |   |  XOR back |  |
   | 30 stages |   | XOR key   |   | event bus |   |           |  |
   +-----------+   +-----------+   +-----------+   +-----------+  |
                                                                  |
        +---------------------------------------------------------+
        v
   +-----------+   +-----------+   +-----------+   +-----------+
   | Go (opt.) |-->| Rust(opt.)|-->|     C     |-->| Assembly  |--> stdout
   | checksum  |   | validator |   | 95 guards |   |  syscall  |
   +-----------+   +-----------+   +-----------+   +-----------+
```

Оркеструє все Python, збирає і ганяє Bash. YAML, TOML, JSON і XML конфіги навмисно
суперечать один одному (`config/`). Читається тільки `pipeline.json`.

## Що робить кожна ланка

| # | Мова | Файли | Що робить |
|---|------|-------|-----------|
| 1 | Java | `src/java/HelloEnterprise.java` | Фабрики, білдери, DI-контейнер, event bus, 95 класів по одному на кожен ASCII-символ, 30-етапний pipeline. Видає коди символів |
| 2 | C++ | `src/cpp/` | XOR-ключ рахується шаблонною рекурсією (Fibonacci mod 251) на етапі компіляції, 256 `static_assert` |
| 3 | JavaScript | `src/js/` | Event bus і 40 middleware, які перевіряють дані й нічого не міняють |
| 4 | Perl | `src/perl/decoder.pl` | Розшифровує XOR (з числовим контекстом, бо Perl). Запасний варіант: `src/python/decoder.py` |
| 5 | Go (опц.) | `src/go/` | Рахує контрольну суму. Пропускається, якщо нема `go` |
| 6 | Rust (опц.) | `src/rust/` | Перевіряє, що все друковане ASCII. Пропускається, якщо нема `rustc` |
| 7 | C | `src/c/` | 95 згенерованих валідаторів, збирає рядок |
| 8 | Assembly | `src/asm/printer_*.s` | Своя версія під кожну платформу, `read`/`write`/`exit` через syscall. Єдине місце, де текст реально друкується. Запасний варіант: `src/c/printer_fallback.c` |

## Платформи

Оркестратор сам визначає ОС і процесор (`python3 orchestrator/main.py --info`) і вибирає
асемблерну версію. Якщо її нема або вона не збирається, ланка тихо замінюється на C.

| Платформа | Асемблер | Статус |
|-----------|----------|--------|
| Linux x86-64 | `printer_linux_x86_64.s` (`as` + `ld`) | протестовано |
| Linux ARM64 | `printer_linux_arm64.s` (`as` + `ld`) | не тестувалось |
| macOS Apple Silicon | `printer_macos_arm64.s` (`cc`) | не тестувалось |
| macOS Intel | `printer_macos_x86_64.s` (`cc`) | перевірено тільки синтаксис |
| Windows / все інше | немає, працює C-замінник | не тестувалось |

Запасні варіанти (C замість асемблера, Python замість Perl) протестовані: `--portable`
примусово вмикає їх.

## Запуск

Потрібно: `python3`, `java` (21 перевірено), `node`, `g++`, `gcc`. Опційно `perl`, `go`, `rustc`.
На Linux для асемблера ще `as`/`ld` (binutils), на macOS достатньо Xcode Command Line Tools
(`xcode-select --install`). На Windows найпростіше через WSL2 або Docker; напряму потрібен
MinGW (`g++`, `gcc` у PATH), і запускати так: `python orchestrator/main.py`.

```bash
make run                              # або ./scripts/run.sh
./scripts/run.sh --message "Hello, Pasha!" --verbose
./scripts/run.sh --portable           # без асемблера і Perl
make test                             # 22 тести + smoke test чистими shell-пайпами
make stats                            # скільки рядків
make generate                         # перегенерувати згенеровані файли
```

Через Docker (збирає все, включно з Go і Rust):

```bash
docker compose up --build
```

## Нотатки

- Java-файл, C-валідатори, C++ asserts і JS middleware **згенеровані** скриптами в `tools/`.
  Результат закомічений у проєкт, щоб його можна було читати й рахувати рядки.
- Повідомлення має складатися з друкованого ASCII (коди 32-126). Кирилиця відхиляється на
  першій ланці: Java дуже серйозно ставиться до своїх 95 провайдерів.
- `make test` на macOS/Windows не гарантовано: частина тестів звертається до бінарників напряму.
- Go і Rust ланки не перевірялися в середовищі, де цей проєкт створювався (там не було
  компіляторів). Якщо в тебе вони є, а збірка падає, оркестратор просто пропустить ланку
  з попередженням.
